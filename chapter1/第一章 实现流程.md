# 第一章：用 Node.js + TypeScript 实现简单智能体

## 1. 实现目标

本章要使用 Node.js 和 TypeScript，从零实现一个简单的智能旅行助手。

用户可以向它提出下面这类任务：

> 请帮我查询今天北京的天气，然后根据天气推荐一个合适的旅游景点。

智能体不会在代码中写死每一步，而是由大语言模型根据当前任务和已获得的信息，自主决定下一步行动。

一次典型的执行过程是：

```text
用户提出任务
    ↓
LLM 决定调用 get_weather
    ↓
程序执行天气工具
    ↓
天气结果作为 Observation 返回给 LLM
    ↓
LLM 决定调用 get_attraction
    ↓
程序执行景点搜索工具
    ↓
搜索结果作为 Observation 返回给 LLM
    ↓
LLM 生成 finish 动作和最终答案
```

这就是一个简化的“决策—行动—观察”循环。

## 2. 项目结构

本章实现的项目位于 `chapter1/travel-agent`，结构如下：

```text
travel-agent/
├── src/
│   ├── agent.ts       # 智能体主循环
│   ├── index.ts       # 程序入口
│   ├── llm.ts         # 大语言模型客户端
│   ├── prompt.ts      # 系统提示词
│   └── tools.ts       # 天气和景点工具
├── .env               # API Key，不能提交到 Git
├── .gitignore
├── package.json
├── package-lock.json
└── tsconfig.json
```

每个文件只承担一类职责：

| 文件 | 职责 |
| --- | --- |
| `prompt.ts` | 告诉模型角色、工具和输出协议 |
| `tools.ts` | 访问外部天气和搜索 API |
| `llm.ts` | 把 Prompt 发送给大语言模型 |
| `agent.ts` | 解析模型动作、调用工具、维护历史并控制循环 |
| `index.ts` | 接收用户输入并启动智能体 |

## 4. 第二步：配置 TypeScript

创建 `tsconfig.json`：

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "NodeNext",
    "moduleResolution": "NodeNext",
    "rootDir": "src",
    "outDir": "dist",
    "strict": true,
    "esModuleInterop": true,
    "skipLibCheck": true
  },
  "include": ["src/**/*.ts"]
}
```

重要配置说明：

- `target: ES2022`：生成现代 JavaScript。
- `module: NodeNext`：使用 Node.js 的 ESM 模块规则。
- `rootDir`：源码放在 `src`。
- `outDir`：编译结果放在 `dist`。
- `strict: true`：启用严格类型检查。

在 `package.json` 中加入：

```json
{
  "type": "module",
  "scripts": {
    "dev": "tsx src/index.ts",
    "build": "tsc",
    "start": "node dist/index.js"
  }
}
```

三个命令的用途：

```bash
npm run dev
```

直接运行 TypeScript，用于开发和调试。

```bash
npm run build
```

执行类型检查，并将 TypeScript 编译到 `dist`。

```bash
npm start
```

运行编译后的 JavaScript。

> 项目使用 `NodeNext` 时，TypeScript 源码中的本地导入要写成 `./tools.js`，而不是 `./tools.ts`。TypeScript 编译时会正确找到对应的 `.ts` 文件。

## 6. 第四步：定义智能体协议

在 `src/prompt.ts` 中定义系统提示词。它需要告诉模型：

1. 它是什么角色。
2. 它有哪些工具。
3. 每个工具需要哪些参数。
4. 它应该以什么格式输出。
5. 什么时候应该结束任务。

项目中使用 JSON 协议，而不是直接解析文档中的 `Thought: ... Action: ...`。JSON 更容易用程序验证，出错时也更容易定位。

调用天气工具时，模型应该输出：

```json
{
  "plan": "先查询北京的实时天气",
  "action": {
    "type": "tool",
    "name": "get_weather",
    "arguments": {
      "city": "北京"
    }
  }
}
```

完成任务时，模型应该输出：

```json
{
  "plan": "已经获得天气和景点信息",
  "action": {
    "type": "finish",
    "answer": "给用户的最终答案"
  }
}
```

`plan` 只是简短的行动摘要，不需要让模型输出详细的内部推理过程。

这一阶段的核心收获是：**Prompt 不只是问题，它还是模型和程序之间的通信协议。**

## 7. 第五步：实现天气工具

在 `src/tools.ts` 中实现：

```ts
export async function getWeather(city: string): Promise<string> {
  const url = `https://wttr.in/${encodeURIComponent(city)}?format=j1`;

  try {
    const response = await fetch(url, {
      headers: {
        "User-Agent": "travel-agent-demo",
      },
      signal: AbortSignal.timeout(10_000),
    });

    if (!response.ok) {
      return `错误：天气接口返回 HTTP ${response.status}`;
    }

    const data = (await response.json()) as {
      current_condition?: Array<{
        weatherDesc?: Array<{ value?: string }>;
        temp_C?: string;
        FeelsLikeC?: string;
        humidity?: string;
      }>;
    };

    const current = data.current_condition?.[0];

    if (!current) {
      return `错误：没有查询到 ${city} 的天气数据`;
    }

    const description = current.weatherDesc?.[0]?.value ?? "未知天气";
    const temperature = current.temp_C ?? "未知";
    const feelsLike = current.FeelsLikeC ?? "未知";
    const humidity = current.humidity ?? "未知";

    return [
      `${city}当前天气：${description}`,
      `气温：${temperature}℃`,
      `体感温度：${feelsLike}℃`,
      `湿度：${humidity}%`,
    ].join("，");
  } catch (error) {
    const message = error instanceof Error ? error.message : String(error);
    return `错误：查询天气失败，${message}`;
  }
}
```

这个工具做了以下工作：

1. 使用 `encodeURIComponent` 处理中文城市名称。
2. 向 `wttr.in` 发送 HTTP 请求。
3. 检查 HTTP 状态码。
4. 将 JSON 返回值转换为 TypeScript 可处理的对象。
5. 提取天气、气温、体感温度和湿度。
6. 将异常转换为 Observation，避免整个智能体直接崩溃。
7. 使用超时限制，防止请求长时间卡住。

## 8. 第六步：实现景点搜索工具

`getAttraction(city, weather)` 负责根据城市和已查到的天气搜索景点。实现要点如下：

```ts
type TavilySearchResponse = {
  answer?: string;
  results?: Array<{
    title?: string;
    url?: string;
    content?: string;
  }>;
};

export async function getAttraction(
  city: string,
  weather: string,
): Promise<string> {
  const apiKey = process.env.TAVILY_API_KEY;

  if (!apiKey) {
    return "错误：没有配置 TAVILY_API_KEY";
  }

  const query =
    `${city}在“${weather}”天气条件下，适合游览的旅游景点推荐。` +
    `请说明推荐理由，并优先考虑天气适宜性。`;

  try {
    const response = await fetch("https://api.tavily.com/search", {
      method: "POST",
      headers: {
        "Content-Type": "application/json",
      },
      signal: AbortSignal.timeout(15_000),
      body: JSON.stringify({
        api_key: apiKey,
        query,
        search_depth: "basic",
        include_answer: true,
        max_results: 3,
      }),
    });

    if (!response.ok) {
      const body = await response.text();
      return `错误：景点搜索接口返回 HTTP ${response.status}，${body}`;
    }

    const data = (await response.json()) as TavilySearchResponse;

    if (data.answer) {
      return data.answer;
    }

    const results = data.results ?? [];

    if (results.length === 0) {
      return `没有搜索到适合 ${city} 当前天气的景点`;
    }

    return results
      .map((result, index) => {
        const title = result.title ?? "未知景点";
        const content = result.content ?? "暂无介绍";
        const url = result.url ?? "无链接";
        return `${index + 1}. ${title}\n${content}\n来源：${url}`;
      })
      .join("\n\n");
  } catch (error) {
    const message = error instanceof Error ? error.message : String(error);
    return `错误：搜索景点失败，${message}`;
  }
}
```

该函数不使用大模型自己的记忆猜测景点，而是通过搜索 API 获取外部信息。这是智能体“通过工具影响和观察外部环境”的具体体现。

## 9. 第七步：接入大语言模型

在 `src/llm.ts` 中完成模型调用：

```ts
import OpenAI from "openai";

const apiKey = process.env.OPENAI_API_KEY;
const baseURL = process.env.OPENAI_BASE_URL;
const model = process.env.OPENAI_MODEL;

if (!apiKey) {
  throw new Error("没有配置 OPENAI_API_KEY");
}

if (!model) {
  throw new Error("没有配置 OPENAI_MODEL");
}

const client = new OpenAI({
  apiKey,
  ...(baseURL ? { baseURL } : {}),
});

export async function generate(
  prompt: string,
  systemPrompt: string,
): Promise<string> {
  console.log("正在调用大语言模型……");

  const response = await client.responses.create({
    model,
    instructions: systemPrompt,
    input: prompt,
    max_output_tokens: 500,
  });

  const text = response.output_text.trim();

  if (!text) {
    throw new Error("模型返回了空内容");
  }

  return text;
}
```

其中：

- `instructions` 是智能体的系统提示词。
- `input` 是用户任务加上前面各轮的执行历史。
- `max_output_tokens` 限制模型单次输出的最大长度。
- `response.output_text` 是最终需要解析的文本。

### 单独测试模型

```ts
import "dotenv/config";

const result = await generate("请回复：连接成功", "你是一个测试助手。");

```

```bash

```

如果使用的兼容服务不支持 Responses API，则需要根据服务商文档将 `generate` 改成 `client.chat.completions.create(...)`。

## 10. 第八步：定义动作类型

在 `src/agent.ts` 中定义：

```ts
type ToolAction = {
  type: "tool";
  name: "get_weather" | "get_attraction";
  arguments: Record<string, string>;
};

type FinishAction = {
  type: "finish";
  answer: string;
};

type AgentDecision = {
  plan: string;
  action: ToolAction | FinishAction;
};
```

模型每轮只有两种选择：

1. `ToolAction`：请求程序调用一个工具。
2. `FinishAction`：停止循环并返回最终答案。

TypeScript 的联合类型可以让程序通过 `action.type` 安全地判断当前动作。

## 11. 第九步：解析和验证模型输出

模型返回的内容本质上是字符串。即使 Prompt 要求它输出 JSON，程序也不应该直接信任。

`parseDecision` 需要完成：

1. 清理模型可能添加的 Markdown 代码块。
2. 使用 `JSON.parse` 解析。
3. 检查 `plan` 是否存在。
4. 检查 `action` 是否存在。
5. 检查 `action.type` 是否为 `tool` 或 `finish`。
6. 检查工具名称是否在白名单中。
7. 检查 `arguments` 或 `answer` 是否存在。

如果解析失败，不要立即终止智能体。可以将格式错误记录为新的 Observation，让模型在下一轮自我修正。

例如：

```text
Observation: 模型输出格式错误，请严格输出一个 JSON 对象。
```

这体现了智能体的一个重要特征：**它能根据环境反馈调整下一步行为。**

## 12. 第十步：实现工具分发器

模型不会直接执行 TypeScript 函数。它只会生成一份动作请求，再由程序将请求分发到真正的工具。

```ts
async function executeTool(action: ToolAction): Promise<string> {
  if (action.name === "get_weather") {
    const city = action.arguments.city;

    if (!city) {
      return "错误：get_weather 缺少 city 参数";
    }

    return getWeather(city);
  }

  if (action.name === "get_attraction") {
    const city = action.arguments.city;
    const weather = action.arguments.weather;

    if (!city) {
      return "错误：get_attraction 缺少 city 参数";
    }

    if (!weather) {
      return "错误：get_attraction 缺少 weather 参数";
    }

    return getAttraction(city, weather);
  }

  return `错误：未定义的工具 ${action.name}`;
}
```

这里形成了一个安全边界：

```text
模型输出工具请求
    ↓
程序检查工具名称和参数
    ↓
只执行程序预先允许的函数
```

不能将模型输出当成 JavaScript 代码使用 `eval` 执行，否则会产生严重的安全风险。

## 13. 第十一步：实现智能体循环

`runAgent` 是整个项目的核心。

伪代码如下：

```text
将用户问题放入 history

最多执行 5 轮：
    将 history 组合成 Prompt
    调用 LLM
    解析 LLM 返回的 JSON

    如果解析失败：
        记录错误 Observation
        继续下一轮

    如果动作是 finish：
        返回最终答案

    如果动作是 tool：
        执行工具
        将工具结果记录为 Observation

超过 5 轮仍未完成：
    抛出错误并停止
```

`history` 是这个智能体的短期记忆。它会逐步包含：

```text
User Request:
查询北京天气并推荐景点

Assistant Decision:
{"action":{"type":"tool","name":"get_weather",...}}

Observation:
北京当前天气晴朗，气温 26℃

Assistant Decision:
{"action":{"type":"tool","name":"get_attraction",...}}

Observation:
晴天适合游览领和园……
```

如果不保存 Observation，模型就不知道工具已经返回了什么，也无法根据天气继续推荐景点。

最大循环次数是必要的保护措施，可以避免：

- 模型重复调用同一工具。
- 工具失败后无限重试。
- 模型始终不生成 `finish`。
- 循环无限消耗 API 额度和运行时间。

## 14. 第十二步：编写程序入口

`src/index.ts` 负责加载环境变量、读取命令行输入和启动智能体：

```ts
import "dotenv/config";
import { runAgent } from "./agent.js";

const userInput =
  process.argv.slice(2).join(" ") ||
  "你好，请帮我查询一下今天北京的天气，然后根据天气推荐一个合适的旅游景点。";

try {
  const answer = await runAgent(userInput, 5);

  console.log("\n" + "=".repeat(60));
  console.log(`最终答案：\n${answer}`);
} catch (error) {
  const message = error instanceof Error ? error.message : String(error);
  console.error(`\n程序运行失败：${message}`);
  process.exitCode = 1;
}
```

`import "dotenv/config"` 必须尽早执行。因为导入 `agent.ts` 后，它又会间接导入 `llm.ts`，而 `llm.ts` 会立即读取 API Key。

## 17. 常见问题排查

### 17.1 `没有配置 OPENAI_API_KEY`

检查：

- `.env` 是否位于 `travel-agent` 根目录。
- 是否在项目根目录执行 `npm run dev`。
- `index.ts` 第一行是否导入 `dotenv/config`。
- 环境变量名称是否和代码完全一致。

### 17.2 `模型没有返回合法 JSON`

可以：

- 强化 Prompt 中“只输出 JSON”的要求。
- 将错误作为 Observation 返回给模型重试。
- 检查模型是否在 JSON 前后加了说明文字。
- 进一步学习模型服务的结构化输出功能。

### 17.3 天气或 Tavily 请求超时

检查网络，并确认当前环境可以访问相应 API。必要时可适当提高超时时间，但不建议完全取消超时限制。

### 17.4 智能体重复调用工具

检查：

- Observation 是否被添加到 `history`。
- Prompt 是否明确说明获得足够信息后要 `finish`。
- 每轮是否都把完整 `history` 发给模型。
- 是否设置了最大循环次数。

### 17.5 TypeScript 找不到本地模块

在 `NodeNext` 模式中，使用：

```ts
import { getWeather } from "./tools.js";
```

而不是：

```ts
import { getWeather } from "./tools";
```

## 18. 学习总结

### 18.1 智能体不只是一次 LLM 调用

普通的 LLM 问答是：

```text
用户输入 → LLM → 文本回答
```

本项目的智能体是：

```text
用户目标 → LLM 决策 → 工具执行 → 环境反馈 → LLM 再决策
```

智能体的关键不在于一次性生成答案，而在于它能够使用工具，并根据工具返回结果继续调整行动。

### 18.2 LLM 是决策者，不是工具执行者

LLM 负责生成：

```json
{
  "type": "tool",
  "name": "get_weather",
  "arguments": {
    "city": "北京"
  }
}
```

真正执行 `getWeather("北京")` 的是 TypeScript 程序。

这种分工带来两个好处：

- 模型负责处理不确定的自然语言任务和动态决策。
- 程序负责参数校验、权限控制和真实的外部操作。

### 18.3 Prompt 是一份通信协议

好的 Prompt 需要同时说清楚：

- 智能体的目标。
- 可用工具。
- 工具参数。
- 输出格式。
- 完成条件。
- 禁止行为。

如果协议含糊，代码就无法稳定解析模型输出。

### 18.4 Observation 让智能体能够根据环境行动

大模型不会自动知道 TypeScript 函数的执行结果。必须把工具返回值明确加入历史：

```text
Observation: 北京当前天气晴朗，气温 26℃
```

模型在下一轮读到这个 Observation，才能判断应该推荐室外景点还是室内景点。

### 18.5 实际智能体必须有安全边界

本项目已经加入了几个基本边界：

- 工具白名单。
- 工具参数检查。
- JSON 格式验证。
- HTTP 请求超时。
- 最大循环次数。
- API Key 通过环境变量管理。
- 错误作为 Observation，而不是不受控制地终止。

完善的智能体还应考虑调用次数、费用、权限、日志、数据隐私、工具副作用以及人工审批。

### 18.6 Workflow 与 Agent 的区别

如果代码直接写成：

```ts
const weather = await getWeather(city);
const attraction = await getAttraction(city, weather);
```

那么工具顺序是程序员预先固定的，更像 Workflow。

本项目由 LLM 根据用户目标、工具说明和 Observation 动态选择下一步，因此已经具备简单 Agent 的特征。

但 Agent 不代表越自由越好。真实项目中通常会将两者结合：

- 用 Workflow 保证关键业务规则和安全边界。
- 用 Agent 处理自然语言理解、动态选择和结果整合。

## 20. 后续可以继续实现的功能

在完成当前版本后，可以按下面顺序逐步扩展：

1. 增加景点门票和开放时间工具。
2. 为工具参数加入 Zod 或 JSON Schema 验证。
3. 防止智能体在参数完全一致时重复调用工具。
4. 将每轮 Decision、Observation、耗时和错误写入日志。
5. 使用数据库保存用户偏好，实现长期记忆。
6. 当景点门票售罄时，让智能体自动搜索备选方案。
7. 当用户连续拒绝推荐时，让智能体重新询问偏好并调整策略。
8. 为可能产生费用或副作用的工具增加人工确认。
9. 为整个智能体增加自动化测试和固定的评测任务集。

建议一次只增加一项功能，并先确认新增功能可以单独测试，再把它接入智能体循环。
